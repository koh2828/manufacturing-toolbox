# Document Intelligence — Known Limitations

このMVPは、サプライヤーごとのテンプレートと人による原本確認を組み合わせる機能です。未知帳票を完全理解する自動品質判定ではありません。

## 認識と帳票の構造

- 実測は開発にも使った架空3社・6製品・16成績書・20ページです。未知の企業・スキャナー・印刷品質に対する独立検証はまだありません。
- 初回の既定設定では、測定値原文の完全一致76/93、項目と値の厳密な組の一致60/93でした。低信頼フラグが付かない誤読もあり、警告なし・規格内・高信頼スコアは正読を保証しません。[精度報告](ocr-accuracy-report.md)
- 日本語の空白挿入、粘度の誤読、小数点と桁区切りの取り違え、薄いラベル、傾斜、部分欠損などが残ります。`<0.01`、ND、範囲値、±表記などは原文と解釈を分け、通常の一点測定値に置換しません。
- 自動傾き推定は実装していません。角度を指定した再処理は可能で、原本と補正後の位置情報を分離して表の対応を維持します。元画像が読めないセルは補完しません。
- 前処理や言語変更が必ず改善するわけではありません。薄いページではコントラスト／二値化がかえってサプライヤー認識を悪くした例があります。原画像を既定としています。
- 複雑な結合セル、多段表見出し、横向き／縦書き混在、一つのページ内の複数成績書、複数製品の値が交差する表、手書き、印鑑の重なり等は完全な自動抽出対象ではありません。分割・テンプレート修正・原本比較・手動行入力が必要になる場合があります。
- 同じサプライヤーの連続ページを無条件に統合しません。識別情報が欠けた継続ページは分割されることがあります。初回評価では真の16成績書を18文書に分けました。
- PDFの直接テキスト抽出判定は文字量によるヒューリスティックです。部分的なテキスト層や誤った埋め込みテキストでは強制OCRが必要です。PDFテキストの単語ボックスは文字列幅による近似です。
- パスワード保護PDFは対応外です。解除した原本を用意してください。破損ページは他ページと区別して失敗扱いにします。

## 確認、統計、品質承認

文書と行の両方を確認済みにした、解釈が「=」の有限数値だけが品質トレンドへ進みます。未確認・却下・ND・大小関係・範囲・±値は通常の数値分布へ混ぜません。サプライヤー、製品、項目、試験方法、単位、LSL/USLが異なる群は分けます。類似する製品名・単位を推測で統合しません。

CoA値はロット代表値・平均・丸め値である可能性があります。管理図へ渡しても、標本の性質をユーザーが確認するまではCp/Cpk/Pp/Ppkを抑制します。確認後も5点未満やDocument由来のXbar-Rでは指数を抑制します。チェックボックスは統計的妥当性を証明するものではなく、安定性、測定法、独立性、群分け等の判断は必要です。

この保存状態は正式な品質承認、電子署名、改ざんを検出する監査台帳ではありません。製品の合否をAIが決定する機能はありません。

## 容量、速度、保存

| 項目 | 現在の上限・条件 |
|---|---|
| UIでの読込 | 最大10ファイル、各30 MiB、作業中100ページ |
| OCRエンジン内部の防御上限 | 1ファイル50 MiB・PDF100ページ、描画16百万画素、1ページ3万単語 |
| 保存ライブラリ | 2,000文書、合計5万検査行、1万ページ、500原本、原本＋メタデータ概算200 MiB |
| テンプレート | 100件。JSON importは2 MiBまで |
| バックアップ取込 | 280 MiBまで。Schema Version 1のみ |
| 再処理履歴 | ページごとに最大5版。無制限の履歴台帳ではない |

ブラウザの実際の保存上限は上表より小さい場合があります。保存は明示操作で、元PDFの保存は別の選択です。抽出結果のみでも全文OCRと位置情報を含み、暗号化されていません。バックアップにも会社の保管方針が適用されます。サイトデータ削除、ブラウザプロフィール変更、容量回収による消失に備えたクラウド同期はありません。原本を残さなければ再表示には再添付が必要です。

20ページの初回処理は検証機で約14.55秒、モデル初期化約258 msでした。ただしモデルはローカルHTTPで配信した測定であり、公開サイトの初回ダウンロードや社内回線の時間ではありません。配布資産全体約21.7 MB、日英モデル計約4.98 MB（圧縮済み）。必要なCPU版と資産だけを読み込みます。

Chromeプロセス群RSSは約1.37 GB、主スレッドJS heapは約19.8 MBでした。RSSはブラウザ基礎分や共有ページを含み、正確なアプリ専有メモリではありません。主スレッドheapだけではWorker/WASMの使用量を表せません。メモリの少ない社内PCでは少量で確認する必要があります。JSONバックアップの読み書きや大きなExcel出力は一時的にUIを待たせる可能性があります。

## 環境とオフライン

実際のOCR検証はApple M1／macOS／Chrome155で行いました。社内Windows・Edgeの管理ポリシー、低メモリ機、Safari、Firefox、モバイルの全組み合わせは未検証です。会社がWebAssembly、Worker、IndexedDB、ダウンロード、GitHub Pagesを制限している場合には動作しない可能性があります。

`file://` で開いた単独 `Launch.html` ではOCRは動きません。従来の統計・Excel機能は従来どおり使用できます。OCRは公開HTTPS版、または全資産をHTTP配信した構成が必要です。モデルのキャッシュだけで、ブラウザ再起動後の完全オフライン利用を保証するService Worker/PWAは実装していません。

実務の確認・訂正を含めた総作業時間短縮は未測定です。操作時間の参考記録はありますが、「手入力より何倍速い」という実証済みの主張はしません。
